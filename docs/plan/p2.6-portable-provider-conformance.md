## Delivery slices

1. Upgrade the lock to format 2 and recompute both Suite digests from RFC 8785
   canonical content excluding only the top-level digest field.
2. Make the lock verifier strictly validate Suite shape, manifest membership,
   profile inventory, embedded digest, and locked digest in one read.
3. Make the local runner execute the immutable case snapshot returned by the
   verifier against a bounded, read-only source archive of the clean Runner
   revision, using the recorded Go toolchain. Require each case to declare an
   exact mapped-test count and observe all matching tests as distinct, started,
   non-skipped passes in `go test -json`; reject explicit `GOROOT`, resolve and
   reuse one absolute Git path, and disclose the host-tool trust boundary.
4. Add a standalone remote runner for the six discovery cases with strict TLS
   configuration, admitted and same-CA unadmitted URI-SAN identities, bounded
   I/O, cancellation, immutable Contract bytes, and JSON evidence.
5. Run component, full repository, Contract, local 50-case, and real local
   black-box gates; then refresh only active evidence locks and documentation.

## Release gates

- `gofmt`, full race/shuffle tests, and `go vet` pass.
- Contract lock verification recomputes both Suite digests and rejects content,
  declaration, digest-profile, manifest, and lock drift.
- The local runner passes all 50 existing cases from the verifier's snapshot.
  Every case declares an exact mapped-test count, all matching tests are
  distinct, started, and non-skipped, and the observed count equals the
  declaration. Tests execute from the Runner revision rather than mutable
  worktree source.
- The remote runner passes all six cases against a separately started local
  Provider through its HTTPS listener, and rejects both an absent client
  certificate and a chain-valid but unadmitted URI SAN.
- The remote report pins exact Contract revision/tree and remote Suite identity,
  exact unmodified runner revision, no Contract mutation-route calls, and
  whether a POST, PUT, PATCH, or DELETE discovery-path probe was actually
  written. `unsafe_method_probes_sent` becomes true only after that write. It
  contains no credentials, bearer material, private paths, opaque references,
  or backend diagnostics, and makes no unscoped conformance or zero-side-effect
  claim.

At implementation `3fe314a` and E2E lock refresh `ae476fe`, the root and E2E
race/shuffle and vet gates, Contract verifier, clean VCS-built 50-case local
Runner, clean VCS-built six-case remote Runner against a separately started

## Non-goals

This plan does not qualify an independently implemented caller, execute
protected or mutating Provider routes remotely, add missing lifecycle cleanup
routes, or claim aggregate, multi-controller, multi-tenant, HA, deployment, or
production readiness.
