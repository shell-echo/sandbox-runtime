# P1.2 Asynchronous Lifecycle Plan

Status: P1.2.0 Contract/ADR implementation in progress on
`codex/p1.2-contract-inventory`; no runtime lifecycle behavior is implemented.
Planning started after P1.1d passed on main merge
`e2755f5573d54a88e389e3f9a1ff289dc153aba5` and post-merge CI run
`32365284283`. No P1.2 lifecycle behavior or Provider lifecycle route is
implemented. The current repository-owned Contract still defines discovery and
protected-admission inputs only; lifecycle behavior must not be invented from
the OpenAPI narrative or local `/instances` API.

## Authority and boundary

The order of authority is:

1. the locked repository-owned MIT Provider Contract, including lifecycle
   Schemas, semantic rules, fixtures, and Conformance Suite cases once added;
2. `docs/architecture.md` and ADR 0001;
3. this plan and any accepted lifecycle ADRs; and
4. implementation details.

The calling platform remains authoritative for tenant/user authorization,
desired state, ProviderRevision selection, aggregate operation truth, retries,
and final workflow status. This service owns only provider-local sandbox
observations, execution progress, reconciliation evidence, and bounded
Provider responses. Provider DTOs remain separate from `instance` and driver
models.

## Contract stop condition

The current Contract does not yet authorize lifecycle request/response schemas,
operation state transitions, lease documents, event cursors, or lifecycle error
wire mappings. Before any lifecycle route, repository, or coordinator behavior:

- add the lifecycle resources to the local Contract with an additive `v1`
  revision or a new namespace when a breaking change is required;
- add semantic rules for idempotency, generations, fencing, deadlines,
  leases, unknown outcomes, and event ordering;
- add valid and rejection fixtures plus executable Suite case IDs;
- update the lock, projection tests, and CI Contract gate together; and
- record any ownership or reliability choice in an ADR.

If a required lifecycle status or error has no Contract authority, stop that
slice. Do not copy or restore an absent external Contract.

## Scope

P1.2 will eventually provide a bounded asynchronous lifecycle subset:

- durable sandbox and Provider-local operation records;
- idempotent create/restore and desired-state requests;
- generation and fencing checks before backend dispatch;
- deadlines, leases, cancellation intent, and `outcome_unknown` handling;
- restart reconciliation and orphan cleanup evidence; and
- durable, monotonically sequenced events and bounded operation reads.

The application/coordinator owns lifecycle policy and operation progress without
Gin, Docker, or external platform truth. Repositories provide explicit atomic
ports. Drivers expose only backend actions and typed observations.

## Non-goals

P1.2 does not claim:

- an external caller or Agent Platform end-to-end compatibility;
- multi-controller production safety from a single-process file repository;
- multi-tenant isolation, deployment readiness, or production readiness;
- exec, terminal, snapshots, browser, desktop, or artifact capabilities before
  their own Contract and gates; or
- changes to the local `/instances` management API.

## Delivery sequence

### P1.2.0: lifecycle Contract and authority inventory

Status: in progress. ADR 0004 and the first bounded additive Contract
resources are being prepared; the lock update and CI evidence remain pending.

Inventory the lifecycle operations in architecture against the current local
Contract, write the lifecycle ADRs, define the minimal additive schemas and
semantic rules, add fixtures and Suite cases, and bind the reviewed Contract
tree. No runtime behavior changes.

### P1.2.1: pure lifecycle domain

Implement backend-neutral sandbox, operation, lease, generation, fencing, and
event value objects plus deterministic transition functions. Tests cover valid
transitions, invalid transitions, deadlines, cancellation intent, unknown
outcomes, and bounded identifiers. No HTTP, persistence, or driver calls.

### P1.2.2: atomic repository ports and development adapters

Define repository ports for sandboxes, operations, leases, and events. Add
memory and single-controller file adapters with atomic idempotency/fencing
reservation, monotonic event sequencing, corruption rejection, restart loading,
and explicit durability errors. Do not call these adapters multi-controller
safe.

### P1.2.3: provider-local coordinator and reconciliation

Compose the domain and repository ports with runtime driver ports. Preserve
context cancellation/deadlines, classify known failure versus unknown outcome,
reconcile after restart, and prove stale attempts cannot overwrite newer
generation/fencing state. No public lifecycle route until the Contract
projection exists.

### P1.2.4: Provider API lifecycle projection

Add only Contract-authorized routes and DTO projections. Reuse the existing
protected-admission boundary before any repository or driver dispatch. Return
stable bounded errors, operation resources, lease state, and event cursors
without backend IDs, host paths, diagnostics, or credentials.

### P1.2.5: lifecycle release gate

Run the locked lifecycle Suite and fault/concurrency matrix: duplicate create,
restart, stale fencing, generation conflict, create/terminate race, lease
expiry, orphan cleanup, cancellation, unknown outcome, event ordering, and
security-base cases. Require PR CI, post-merge CI, and explicit evidence for
any caller, reliability, tenancy, deployment, or production claim.

## First implementation entry

The next implementation slice is the reviewed Contract lock update for ADR 0004.
P1.2.1 and all lifecycle code remain blocked until the lifecycle Contract
resources and lock are reviewed and pass the local Contract gate.
