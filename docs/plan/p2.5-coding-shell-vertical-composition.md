## Objective

Compose the already bounded P2 components into one honest, runnable Provider
profile without crossing Agent Platform ownership boundaries or promoting
local evidence to external compatibility.

The P2 release gate remains the architecture gate: a separately supplied caller
must run its coding and shell scenarios against this Provider without backend
endpoint leakage or cross-tenant access. This plan first makes such an E2E
technically possible; it does not replace the independent caller.

## Verified Starting Point

The 2026-08-26 audit established:

- Contract namespace `urn:shell-echo:sandbox-runtime:provider-v1`, revision
  `6f549c222ab5ff5b57ed1a49bd2ac5bb95d3b311`, tree
  `b27453d048a2cd8b90f54008d5c4eac28f38c9cb`, and 35 local Suite cases;
- capability semantics are `zero-or-terminal-only` and forbid non-terminal
  advertisement;
- the command root composes Provider lifecycle only, using a fake lifecycle
  driver;
- exec has Contract/domain/coordinator/ledger evidence but no Provider HTTP
  application dispatch or real executor;
- terminal, Gateway, artifact, usage, and operation-family components exist but
  are not assembled into the command root with real adapters;
- startup advertises empty capability and runtime-profile arrays;
- no stable four-mount Provider runtime or real WebSocket adapter exists; and
- no independently owned caller/platform scenario is runnable.

These are implementation and environment facts, not a conclusion that the
individual P2 component gates failed.

P2.5b has since locked revision
`22a148e2898477790512d5bb742605654ff00ebf`, tree
`1a967c9c6ce9646c8431f6ee48699ec9f406a589`, and 38 local Suite cases. It
permits empty, terminal-only, or atomic exec+terminal advertisements while the
command composition remains empty by default.

## Ownership and Non-goals

The Agent Platform continues to own WorkOrder, Run, tenant/user authorization,
ProviderRevision selection, Artifact publication, billing/accounting, aggregate
operation truth, and public Gateway policy. The Provider owns only local
execution and bounded evidence.

P2.5 does not establish aggregate conformance, distributed authorization,
multi-controller operation, hostile multi-tenant isolation, deployment, or
production readiness. It does not add browser, desktop, snapshot/restore, GPU,
nested-container, or port-forward capabilities. It does not reuse `/instances`
wire DTOs or repository truth.

### P2.5c: mutation preflight ordering

Local result: create and runtime-session unknown-field and encoded-body-limit

### P2.5d: Provider runtime foundation

Add a Provider-specific runtime port and real development adapter with:

- stable `/inputs` read-only, `/workspace` mutable, `/outputs` staging, and
  bounded `/tmp` mounts;
- pinned image, numeric non-root identity, read-only root, resource bounds,
  ownership labels, network policy, and cleanup;
- lifecycle create/observe/remove behavior with context cancellation,
  idempotency, restart recovery, and unknown-outcome evidence; and
- opaque backend-neutral observations with no host/backend identifiers in
  Provider projections.

The adapter may share low-level engine primitives but not local `/instances`
DTO, repository, or business state.

Gate: focused fault/restart tests, full Go gates, and tagged Docker integration.
This remains single-controller development evidence.

Local result: commit `de18787` adds a Provider-specific Docker lifecycle
adapter and explicit development configuration without importing local
`instance` models or repositories. It supplies the four stable guest paths,
fixed isolation/resource/ownership controls, idempotent create/observe/remove,
restart reconciliation, unknown-outcome evidence, and cleanup. Focused and full
race/shuffle, vet, unchanged Contract verification, the 38-case Suite, diff
checks, and live integration for both Docker packages passed. Post-push CI
`32929140044` passed `provider-contract`, `test`, and the expanded
`docker-integration` job; advertisement remains empty and no production or
external-caller claim is made.

### P2.5e: exec vertical

Compose protected exec, cancel, operation read, and retained result routes over
durable acceptance, the existing coordinator/ledger, a real executor/canceler,
result capture bounds, usage correlation, and reconciliation.

Gate: accept-before-dispatch, idempotent replay/conflict, generation/fencing,
deadline/cancellation, application exit versus provider failure,
outcome-unknown, restart, expiry, truncation, and no-backend-leakage matrices.

Local result: commit `5917a57` composes strict protected exec, cancellation,
result, and operation routes over an independent durable file ledger and the
Provider Docker runtime. It preserves durable accept-before-dispatch, temporal
and identity correlation, restart and on-demand reconciliation, terminal
operation summaries after result expiry, bounded private stdout/stderr capture,
truncation, nonzero application exits, cancellation confirmation, and
identity-bound cleanup. Unsupported environment, secret, and stdin references
fail before durable acceptance. Focused and full race/shuffle, vet, unchanged
Contract verification, the locked 38-case Suite, diff checks, and live
integration for both Docker packages passed. Usage correlation is minimal; the
real collector remains P2.5g. Post-push CI `32937530059` passed all three jobs
for evidence baseline `2f7a79b`. This is single-controller development and
repository CI evidence only, with no advertisement, external-caller,
aggregate, multi-controller, multi-tenant, deployment, or production claim.

### P2.5f: terminal and Gateway vertical

Compose session authority and persistence with a real terminal allocator,
opaque handoff resolver, concrete bounded WebSocket adapter, and the existing
Gateway authorization/proxy boundary.

Gate: accept-before-allocation, terminal process cleanup, opaque endpoint
non-disclosure, expiry/generation/revocation interruption, reconnect bounds,
bidirectional frames, restart behavior, and metadata-only audit evidence.

P2.5f0 audit result: the P2.5e Docker exec stream is non-TTY, has no stdin, and
cannot be reconstructed after Provider restart. Reusing it would not satisfy
terminal reconnect or restart evidence. The vertical is therefore split in
the [P2.5f terminal/Gateway plan](p2.5f-terminal-gateway-vertical.md): f1
reconnectable runtime/broker port and Docker adapter, f2 durable coordination
and session repository migration, f3 opaque reference registry/resolver, f4
WebSocket and terminal stream adapters, f5 Gateway composition with injected
caller-owned ports, f6 command/recovery/shutdown composition, and f7 the local
evidence gate. Resize and explicit close-session semantics remain outside the
current Contract; capability advertisement remains empty through this work.

P2.5f1 local result: commit `6778d3c` adds a backend-neutral terminal runtime
port and a Docker development adapter backed by an in-sandbox PTY broker. The
adapter persists container, broker-exec, and Unix-socket identity only in its
private state and returns an opaque `ref:terminal/*` receipt. Focused tests
cover idempotent allocation, lost start responses, identity conflicts,
per-sandbox/per-controller capacity, expiry, cancellation, sandbox removal,
corrupt private state, and idempotent process-group cleanup. Live Docker
integration proves that a shell variable and broker exec identity survive
Provider driver reconstruction and a fresh attach. Full race/shuffle, vet,
module verification, unchanged Contract verification, the locked 38-case
Suite, diff checks, and both Docker integration packages passed locally. The
test builds the broker into writable `/workspace`; production packaging at a
fixed read-only image path remains unproven. No session repository migration,
coordinator, `ref:session:*` resolver, WebSocket, Gateway composition, command
configuration, advertisement, or external-caller evidence is claimed.
Post-push CI `33033284420` passed `provider-contract`, `test`, and
`docker-integration` for evidence baseline `66dd3d1`; it does not expand those
claims.

### P2.5g: artifact and usage vertical

Compose artifact acceptance with a real `/outputs` reader/stager, injected
tenant-binding/active-content/malware checks, retained evidence, usage
collection, and all-family operation aggregation.

Gate: durable accept-before-dispatch, missing/rejected/staged/unknown/expired
states, digest/media/size enforcement, usage correlation and reconciliation,
restart behavior, and absence of publication or billing authority.

### P2.5h: readiness-derived composition and advertisement

Add explicit configuration and a startup dependency graph for the canonical
profile. An explicitly enabled incomplete profile fails startup. A disabled
profile advertises empty arrays. A successfully enabled profile advertises only
the exact locked capabilities and runtime profile, from an immutable snapshot.

Gate: dependency-absence matrix, config validation, startup/shutdown cleanup,
advertisement-to-route/profile consistency, complete local Suite, full Go
gates, and tagged Docker integration.

### P2.5i: independent caller release gate

Requires externally supplied inputs:

- independent caller checkout and executable scenario runner;
- exact Contract namespace, revision/tree, and Suite identity;
- caller and Provider mTLS PKI plus JWS trust material;
- deployable Provider, Gateway, and real runtime configuration; and
- at least two authorization/tenant contexts for negative isolation attempts.

Run lifecycle, exec/cancel/result, terminal/Gateway, artifact/usage,
restart/reconciliation, expiry, endpoint non-disclosure, and cross-tenant
negative scenarios. Record exact commands, configuration digests, image digest,
logs/artifacts, and outcomes. Local Suite mappings, fakes, and same-process
integration tests are not substitutes.

Gate: the architecture P2 caller release gate passes. Only then may P3 external
shadow, canary, rollback, and old-run drain work begin.


```bash

```
