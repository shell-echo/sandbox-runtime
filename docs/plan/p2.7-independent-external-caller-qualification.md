# P2.7 Independent External Caller Qualification Plan

Status: **Definition in progress; no qualification result yet.** P2.7a locks the
verified `sandbox-runtime-external-caller-coding-shell-v1` machine-readable
definition authority. The closed report schema, report/evidence validator,
adapter protocol, harness, and independently supplied caller execution remain
open.

## Authority and Scope

The locked Provider Contract controls wire behavior. ADR 0040 controls the
independence and evidence boundary. The
[`external-caller-coding-shell-v1`](../qualification/external-caller-coding-shell-v1.md)
profile explanation and its content-addressed
[`profile.json`](../../qualification/external-caller-coding-shell-v1/profile.json)
control the exact topology and scenario inventory. The machine profile outranks
the explanatory text when they differ.

This plan does not authorize Provider-side consumer adapters. The external
consumer supplies and versions its own adapter. Repository work may implement a
generic evidence validator and bounded orchestration hooks, but it must not
generate the caller's protected requests or reuse the `e2e/` caller as external
evidence.

## Delivery Slices

### P2.7a: qualification authority

Status: complete for the definition authority at digest
`sha256:baee769c0acc395448af61faef99cd97fbb63ccb83c70eb51915952be519991a`.

- define independently supplied caller and adapter identities;
- distinguish caller-owner assertions from observed evidence;
- lock the 15 initial and 5 reconstruction case IDs, dependencies, interactions,
  expected status/error policies, required assertions, and independent
  observation sources;
- lock actual executed-artifact identity, distinct-tenant topology, caller-owned
  reconstruction state, numeric limits, and non-self-referential evidence
  receipt rules;
- require a dedicated disposable target and bounded out-of-band teardown; and
- retain explicit Suite, multi-tenant, deployment, and production non-claims.

The machine profile and schema bind each interaction and each required
observation to its actor, source, subject, and correlation; define per-artifact
digest subjects, observers, owners, source/release requirements, trust domains,
and separate configuration identities; bind reconstruction to a sanitized
invocation transcript and shell-state challenge; make cleanup inventory and
receipt digests canonical and non-vacuous; and define asynchronous polling,
cancellation-operation reconciliation, counter boundaries, file-count scope,
and clock anchors. The dedicated verifier checks its closed shape, semantic
cross-field rules, exact 15+5 case, 41-interaction, and 91-observation inventory,
schema digest, and profile digest.

No Provider wire or runtime behavior changes in this slice.

### P2.7b: evidence schema and validator

Add a closed, versioned qualification report schema and a standalone validator.
The validator must reject unknown or duplicate fields, oversized input,
reordered or missing scenarios, incomplete identities, Suite overclaims,
missing mutation/cleanup evidence, failed sanitization, and trailing data. It
must not ingest credentials, raw requests, raw Provider responses, or private
caller configuration.

The validator reads the evidence root, not an isolated report: it rejects
symlinks, non-regular files, path escape, replacement while opening, duplicate
paths, per-file and aggregate size overflow, payload digest mismatch, and
private material. It emits a bounded external `receipt.json` that hashes the
exact raw report bytes and verified payload inventory. Validation proves report
and payload consistency only. Caller ownership, source hosting, build systems,
operating systems, and network paths remain explicit trust inputs.

### P2.7c: external adapter process boundary

Define a language-neutral, bounded process protocol through which a
consumer-owned adapter receives one qualification invocation and reports
scenario progress. The caller and adapter expose their embedded Contract,
profile, and release identities before receiving harness expectations. Secrets
use dedicated inherited channels or ephemeral files with bounded lifetime; they
do not appear in argv, environment snapshots, reports, or logs.

The harness must prove that the external process, not repository caller code,
constructs protected requests. It records the adapter artifact digest and
process identity, enforces output bounds and deadlines, and kills then waits for
the process on cancellation or protocol failure. Reconstruction does not
re-inject caller correlation bindings. No consumer-specific adapter is added to
this repository.

### P2.7d: disposable black-box harness

Compose the exact Provider revision, runtime image, external caller adapter,
caller-owned Gateway, two admitted controllers in different tenants, one
same-CA denied identity, persistent state, reconstruction phase, evidence
capture, independent observers, authoritative resource inspector, and
operator-owned teardown.

The harness performs all preflight checks and captures the resource baseline
before enabling mutations, enforces every numeric profile bound, records a
cleanup obligation after a mutation may have been written, and always attempts
cleanup under a separate bounded context. It verifies the post-teardown
inventory equals baseline with zero run-owned resources before finalizing
evidence.

### P2.7e: external qualification run

Run the profile with a caller artifact supplied from outside this repository.
Inspect the exact sanitized evidence set and record its digest. An unavailable
external caller or environment leaves the gate without a result; it is not a
Provider failure and cannot be replaced with the repository reference caller.

## Release Gate

- the caller and its adapter have immutable external identities and satisfy the
  ADR 0040 independence boundary;
- all 15 initial and 5 reconstruction scenarios execute and pass;
- Contract, Suite, profile, and the actual executed Provider, runtime, caller,
  adapter, Gateway, observer, inspector, teardown, topology, and configuration
  identities are exact;
- caller assertions correlate with every machine-profile-required independent
  observation, and reconstructed caller state was not supplied by the harness;
- mutation and unknown-outcome cleanup obligations are complete, teardown
  passes, and zero run-owned runtime resources remain;
- the closed evidence report and exact file set pass the validator and private
  material scan; and
- component, Conformance Suite, external-caller, multi-controller,
  multi-tenant, deployment, and production claims remain separate.

## Non-goals

P2.7 does not implement an external consumer, add a Provider-owned adapter,
change Provider wire behavior, qualify the same-repository reference caller,
define a portable mutating Provider Suite, or establish aggregate,
multi-controller, multi-tenant, HA, deployment, or production readiness.
