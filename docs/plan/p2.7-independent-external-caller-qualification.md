## Authority and Scope

The locked Provider Contract controls wire behavior. ADR 0040 controls the
independence and evidence boundary. The
[`external-caller-coding-shell-v1`](../qualification/external-caller-coding-shell-v1.md)
profile explanation and its content-addressed
[`profile.json`](../../qualification/external-caller-coding-shell-v1/profile.json)
control the exact topology and scenario inventory. The machine profile outranks
the explanatory text when they differ. The closed
[`report.schema.json`](../../qualification/external-caller-coding-shell-v1/report.schema.json)
and
[`validator.semantics.json`](../../qualification/external-caller-coding-shell-v1/validator.semantics.json)
control the report/payload shape and semantic cross-file bindings.
The separately locked
[`adapter-protocol.schema.json`](../../qualification/external-caller-coding-shell-v1/adapter-protocol.schema.json)
and
[`adapter-protocol.semantics.json`](../../qualification/external-caller-coding-shell-v1/adapter-protocol.semantics.json)
control only the harness-to-adapter process protocol. They do not alter Provider
HTTP behavior.

This plan does not authorize Provider-side consumer adapters. The external
consumer supplies and versions its own adapter. Repository work may implement a
generic evidence validator and bounded orchestration hooks, but it must not
generate the caller's protected requests or reuse the `e2e/` caller as external
evidence.

### P2.7b: evidence schema and validator

Status: complete for the closed report and evidence-validation definition at
raw schema digest
`sha256:5d97e10c8b5b2f365e275e78868d5a35d78bbdffdec05ea2f18b5c947cd429f6`
and raw validator-semantics digest
`sha256:c724eaa9f3b52e1a5ba4aa5aaeb5e8b61a744818b2f56fd8ff52dfa5e1e584df`.

The closed, versioned qualification report schema and standalone validator
reject unknown or duplicate fields, oversized input,
reordered or missing scenarios, incomplete identities, Suite overclaims,
missing mutation/cleanup evidence, failed sanitization, and trailing data. It
does not ingest credentials, raw requests, raw Provider responses, or private
caller configuration.

The validator reads the evidence root, not an isolated report: it rejects
symlinks, non-regular or multiply linked files, path escape, replacement while
opening, duplicate paths, per-file and aggregate size overflow, payload digest
mismatch, and obvious private-material markers. The secure Darwin/Linux path
holds one fixed root directory descriptor, uses descriptor-relative
`openat`/`fstatat` with no-follow checks, and creates the `0600` receipt
exclusively without overwrite. Unsupported platforms fail closed.

The qualification operator must stop the payload producer and keep the
validator as the evidence root's exclusive writer from `Verify` entry through
return; other processes with the same UID are included in this exclusion. The
descriptor-relative and TOCTOU checks fail closed on the mutations they detect,
but do not establish root integrity while an attacker retains continuous write
access. Only after successful validation may an external packager archive the
root and bind the resulting archive digest in its artifact envelope.

Receipt publication stages an exclusive random pending file before the final
inventory, report-byte, and receipt-byte rechecks, checks cancellation
immediately before commit, and only then commits `receipt.json` without
overwrite. Failure cleanup is inode-aware and reports cleanup errors. A
different-inode replacement or destination from a handoff-violating writer is
preserved rather than deleted and remains failed-run residue that cannot be
packaged as accepted evidence.

The only payloads are the Provider observer, Gateway observer, process
supervisor, resource inspector, and trusted-input records at their five locked
paths. `passed` or behavioral `failed` requires all five and complete identity;
`incomplete` and `not_executed` may use only explicitly nullable identity fields
and a strict payload subset, while every present value remains validated and
cross-bound. The validator emits a bounded external `receipt.json` that hashes
the exact raw report bytes and verified payload inventory.
An executed scenario with missing required evidence and no observed mismatch is
`incomplete`; it cannot be mislabeled as `passed` or as a proved `failed`
scenario. When mutation evidence exists but the resource-inspector payload is
absent, the report retains the cleanup obligation with no inspector-owned
positive evidence and an `unknown` or `incomplete` cleanup outcome.

Nullable evidence remains fail closed. Run timestamps are all null or all
present; a present process-supervisor payload requires complete, cross-bound
run, phase, and scenario timings. Without it all scenarios are `not_executed`,
timings are absent, and the shell-continuity challenge is null. A passed
scenario requires every locked interaction and required payload-digest-bound
observation.

For a resource-bearing mutation interaction with mismatched outcomes or
required observations, every wire attempt counts as a potential unexpected
resource admission. The validator may therefore reject a conservatively
over-counted run instead of assuming zero allocations. Its
`sandbox_resources` binding is deliberately narrower than the raw request: the
report and Provider observer cross-bind only CPU, memory, ephemeral-storage, and
PID limits, present exactly with the unique `create-sandbox` interaction
regardless of its outcome. They do not bind the complete request bytes or its
digest.

The cleanup `ownership_selector_digest` is bound into the query-scope digest and
the resource-inspector payload's cleanup projection. There is no second
independent selector fact source in P2.7b, so validation proves consistent
binding rather than the underlying selector's independent truth or
completeness.

The evidence root is an operator-supplied healthy local filesystem. Context
cancellation applies at validator stage boundaries and immediately before
receipt commit; it cannot interrupt a synchronous filesystem syscall blocked in
the kernel. P2.7b therefore does not claim a deadline bound for stuck FUSE or
network-filesystem I/O.

Validation proves report and payload consistency only. The semantics locks the
marker set and requires scanning raw bytes, normalized JSON, and decoded JSON
strings, but that scan cannot prove discovery of arbitrary unknown, encoded, or
disguised secrets. Caller ownership, source hosting, build systems, operating
systems, network paths, the validator
implementation, repository revision, build, and host toolchain remain explicit
trust or provenance inputs. The validator-semantics digest locks rules and
payload mappings; it does not attest the executable that enforced them.

The repository CI compiles the locked schema and exercises the evidence-root
and report validator tests. It deliberately does not synthesize an external
caller report or claim a P2.7e result. P2.7b closes only the evidence-definition
slice, not independently implemented caller compatibility.

### P2.7c: external adapter process boundary

#### P2.7c.1: protocol authority

Status: definition locked, with byte-accounting semantics clarified by the
P2.7c.2a codec slice. The closed protocol has raw schema digest
`sha256:fdee270ca27003693b2ce504da769c9779825312e1dd4e06b5caf8578f5ee03c`
and raw operational-semantics digest
`sha256:997c49cd1a5b2c050d48333a973dd78b611221f869bf709cf6d1a8d771795a99`.
The protocol authority is bound through startup identity,
process-supervisor projection, validator semantics, and receipt using the same
ID, version, schema digest, and semantics digest. The semantics also require a
future sanitized transcript projection to include that identity, but no codec
currently emits or recomputes that digest. All qualification Schema compilers
use one ECMA-262 regexp engine, and the locked text patterns reject ASCII
controls without POSIX-only classes. Invocation paths/endpoints now use closed
canonical profiles. The definition requires digest-bound preflight commitment
before the supervisor or harness acquires or generates credential or
forbidden-correlation material, plus cross-phase byte identity; runtime proof
awaits the supervisor and operator-upstream non-derivation remains trusted.
Non-error output invocation IDs and phases now bind to the single validated
inbound invocation, including scenario case-ID phase prefixes. Protocol errors
use disjoint pre-binding and post-binding terminal branches. Deadline control
uses process-supervisor monotonic elapsed time: one 1,800-second execution clock
starts before the first preflight and is never reset by phase process start or
reconstruction; each case receives at most 120 seconds, clipped by the remaining
execution and parent-context deadlines, and neither `scenario_started`, retry,
nor transient output resets it. Deadline expiry preempts events observed at or
after the effective deadline. Failure termination starts its separate five-
second cleanup budget before closing supervisor-owned I/O, then kills the
process group and performs bounded wait/reap. P2.7c.2b.1 now locks the exact
state and transcript definitions; c2b.2-.7 implement state enforcement and
transcript recomputation. Physical deadline and process enforcement remain c3 work.

P2.7c.1 hardening was intentionally split into reviewable slices. Protocol
authority binding, ECMA-262 regexp portability, canonical invocation
locations, output `invocation_id`/phase binding, the `protocol_error` state
branch, and executable deadline anchors are complete definition slices. Each
slice passed its own negative tests and the full repository gates before the
next begins.

The protocol is strict UTF-8 JSON. Each phase has one fresh adapter process and
one EOF-framed invocation; adapter progress is bounded LF-delimited JSON. The
startup identity is output before the harness writes any expectation or
credential byte and declares the caller release, adapter release, Contract,
profile, and protocol identities. The combined startup frame remains a
caller-owner assertion. The process supervisor must independently bind the
actual caller and adapter artifacts and processes.

Only the seven profile-owned harness fields may be supplied. Initial and
reconstruction invocation IDs differ, and reconstruction cannot receive a
sandbox, operation, attempt, idempotency, fencing, runtime-session, or handoff
binding through the invocation, argv, environment, working directory,
credential payload, endpoint query, or state-root seeding. Credential bytes are
reserved for dedicated inherited pipes in the first Darwin/Linux transport
profile and never enter the JSON protocol, logs, or evidence. The JSON data
model is language-neutral; the first process transport is not claimed portable
beyond Darwin/Linux.

Adapter progress uses `completed` or `not_executed` dispositions and is always a
caller-owner assertion. It does not assign the final scenario status or run
outcome. The report validator derives `passed`, `failed`, `incomplete`, or
`not_executed` from adapter claims plus independent observations. In particular,
missing required evidence without an observed mismatch is `incomplete`, while
an observed mismatch is `failed`.

The protocol semantics also lock per-record and aggregate output bounds,
deadlines, secret-channel limits, sanitized transcript fields, and the required
close-I/O, process-group kill, and bounded reap sequence. P2.7c.1 verifies these
definitions only: it launches no process and supplies no external-caller result.

#### P2.7c.2: strict codec and state machine

##### P2.7c.2a: strict codec

Status: implemented. The runtime-independent codec enforces one EOF-framed
invocation, LF-terminated output records, the exact 32 KiB invocation, 64 KiB
record, 33-record, and 2 MiB stdout ceilings, and the locked failure
precedence. Record bytes exclude LF; stdout bytes include delimiters and invalid
or truncated bytes. It rejects invalid UTF-8, duplicate members, invalid
surrogate escapes, multiple values, closed-Schema or direction violations, and
startup protocol-authority mismatches. Decode errors are stable and sanitized,
and the first failure is terminal. It does not validate order or launch a
process.

#### P2.7c.3: process supervisor

**c3.1 implemented:** `internal/qualificationsupervisor.OpenExecutable` rejects
unsupported platforms before filesystem access, requires an explicit absolute
clean path (no PATH lookup or automatic symlink resolution), and traverses each
component with no-follow directory descriptors. It checks the final regular-file
identity before/after opening and retains a read-only close-on-exec descriptor.
Local admission additionally requires a singly linked, nonempty file, at least
one execute bit, no set-id bits, and no group/other write bits. The operator
supplies a positive byte bound capped at 1 GiB; hashing uses bounded buffers and
checks context cancellation between reads. These are supervisor-local safety
restrictions, not new Provider Contract or adapter protocol limits.

`Recheck` verifies the held descriptor, raw SHA-256, size/mode/mtime, and the
current no-follow pathname identity. Only digest and byte length are exported
as initial snapshot metadata. Errors expose no path or inode. Close is
idempotent; this is a single-owner API. The operator must retain exclusive
trusted custody of the artifact and namespace: a descriptor/recheck is not an
immutable snapshot or atomic binding to a future exec. Healthy local filesystems
are required; cancellation does not interrupt a kernel-blocked syscall.
Native loadability, interpreter/dependency identity, mount execution policy and
the actual executed artifact remain later startup/observation gates. No file is
executed in these c3.1 tests. Linux runtime testing was deferred to c3.7 and is
recorded below; cross-builds alone did not close it. **Next at this checkpoint:**
c3.2 configuration/path/state-directory freeze.

**c3.2 filesystem slice:** `OpenLocationFiles` consumes a prepared static
configuration and retains read-only close-on-exec descriptors for the locked
profile, its parent, work/evidence directories, the state parent and newly
created state directory. The profile must be a singly linked regular file of
at most 2 MiB, with no write/set-id/sticky bits and an owner of root or the
effective user. The bounded document reader verifies the locked profile digest;
rechecks bind the original raw bytes, inode, size, mode, ownership and mtime.
Repository Schema/Contract verification remains a separate definition gate.

Directory traversal uses no-follow descriptor-relative opens and records
ancestor identities. Selected existing directories must be owned by root or
the effective user, have no group/other write bits or special bits. Physical
ancestor comparisons supplement lexical overlap checks. State creation uses
exclusive `mkdirat(0700)` against the retained parent and refuses all existing
entries, including empty directories. The opened state identity is rebound to
that parent. The resulting directory must be mode 0700 and owned by the
effective user; restrictive umasks are not repaired. Recheck detects pathname,
inode, permission and ownership replacement, including recorded ancestors.
Directory size/mtime are deliberately not frozen: caller-owned state may evolve.

Production code never enumerates, opens or reads state entries. Its initial
empty-state basis is exclusive directory creation, not inspection of caller
data. Close only releases descriptors. Failures after creation return the
sanitized `ErrStateDirectoryRetained` marker (preserving cancellation), leave
the new directory for operator inspection and never auto-delete it. Existing
state is neither reused nor reported as newly created. Retry needs an explicitly
provisioned fresh path or separately authorized operator cleanup.

These checks require a healthy local filesystem and trusted operator custody
of the namespace. POSIX mode/owner checks do not attest ACL grants, mount
policy, isolation from same-UID processes or atomic binding to a future exec.
The operator must exclude additional ACL grants and untrusted namespace
writers. No kernel-blocked syscall cancellation, mount isolation or hostile
multi-tenant guarantee is claimed. Linux runtime verification was deferred to
c3.7 and is recorded below.

The `LocationFiles` object alone is not a final commitment or phase admission;

**c3.3 actual spawn and ownership:** `StartProcess` uses the shared run parent
bound during configuration preparation, rechecks the frozen admission and empty
work directory, then starts the committed executable without a shell
using explicit argv, an empty environment, cwd and the exact fd 0-10 mapping.

and closes every parent copy of a child endpoint. Copies of the prepared launch
cannot start again. Start failures close unused topology; post-start failures
retain a recovery owner even when cleanup is incomplete. Stdout is reserved for
the protocol decoder and stderr remains private; no raw reader, descriptor, or
input/credential writer crosses the supervisor boundary.

Explicit Close, frozen-owner Close or run-parent cancellation closes owned I/O,
signals the original group plus the direct child, and polls/reaps under a
separate five-second cleanup window. Shared process copies use one cleanup
operation. The child remains unreaped until any required signaling finishes,
keeping its PID reserved before group termination. A Darwin natural-exit test exposed
EPERM on group signaling: this is accepted only after the owned child is reaped
and a non-mutating signal-0 check confirms the group no longer exists. Other
permission failures remain failures. Timeout reports incomplete and leaves one
background reaper attached; repeated closes preserve the cleanup result. No
late signal is sent to a potentially reused group after reap.

Close success means reclamation, not a clean process exit or passing protocol.
A canceled/killed/unreaped process cannot enable reconstruction merely through
supplied protocol completion events. c3.6 below supersedes the earlier synthetic
exit boundary for normal completion; process groups still do not contain escaped
descendants. Healthy kernel/filesystem calls and trusted namespace custody
remain required. These are not atomic exec/cwd or hostile-tenant guarantees.

retaining success stats. Both the per-call context and immutable shared run
